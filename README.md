# 斷踝

手機直式 3D 街頭籃球 1 對 1。開房後朋友掃 QR Code 就能連線對打，也可以打電腦。

## 部署

Cloudflare Workers 匯入這個 repo，部署指令用 `npx wrangler deploy`。設定都在 `wrangler.jsonc`，房間用 SQLite 版 Durable Object，免費方案可用。

## 結構

- `src/worker.js`：把 `/ws/房號` 接到房間，其餘路徑給靜態檔案
- `src/room.js`：一間房的裁判，伺服器跑規則，雙方只送操作
- `src/sim.js`：籃球規則與物理，手機和伺服器共用
- `public/index.html`：遊戲畫面

## 遊戲規則（11 分版）

- 1 對 1，率先累計至少 **11 分**獲勝，三分球計 3 分、灌籃計 2 分。
- 新球權在三分線內取得球時，必須先將持球者帶回（踩到）三分線；後撤步可在踩線後直接銜接投籃，提早按住投籃鍵也能接招。
- **籃下**：禁區沒人擋才會灌籃；防守者貼在你與籃框之間（約 1.9 公尺內且比你更靠近籃框）時灌不了，投籃鍵變成**上籃**，搖桿橫推再按是**歐洲步**（側跨一步再回來，途中也會晃人）。上籃被蓋前再按一次投籃鍵是**拉桿**，閃過封蓋但命中率只有約一半。
- 灌籃遭到封蓋時，有約 **0.7 秒**的短慢動作與綠條拉桿救球機會；救球成功後仍只有 **60%** 會進。
- **防守 B 鍵**：點按＝起跳封蓋（放開時才起跳）；按住 0.12 秒以上＝**舉手**，不離地、移動速度減半、不會被假動作騙，干擾約為起跳的六成，也封蓋不了。
- 干擾依防守者正面 120° 扇形的距離而定，背後不干擾；出手離三分線越遠，窗口與命中率**連續**衰減（沒有斷崖），投到對面籃下的「Logo 球」極難；神準期間只吃一半衰減。
- **抄球**：範圍與成功率比舊版略大，落空仍會讓持球者獲得突破加成；鐵閘的抄截與封蓋加成降低。
- **晃人判定窗**：被晃的人要在約 0.26 秒（連線對戰再加 0.06 秒與延遲補償，上限 0.3 秒，最短不低於 0.2 秒）內把搖桿推向同一邊；只看你推的方向，不再因「本來就在往那邊跑」而放過。站定的防守者頂住突破時，持球者會踉蹌 0.3 秒。
- **手感**：A／B 按太早（無法行動時）會緩衝 0.1 秒，一能動就執行；放開搖桿 0.08 秒內按 A 仍用剛才的方向；絕招鍵遠離招式鍵且需**長按 0.25 秒**。連線時投籃按住時間與補扣按下時刻由手機回報，伺服器只在 ±0.12 秒內採用。
- **能量**：進球不再加能量；完美出手 +5、讀懂晃人 +12、抄截 +30、封蓋 +30、斷踝 +30。
- 斷踝失誤只在**當次攻守球權**中累積，球權轉換或重新開球便清零。單人模式需 2 次，朋友對戰需 3 次，並給網路對戰更多反應時間。
- 球若連續 7.5 秒無人撿到，會重開下一個回合。

## 多人連線（房間模式）

- 房主選「開房跟朋友打（QR Code）」，畫面顯示 QR Code 與 4 碼房間代碼，連結和代碼都可以複製。
- 朋友可掃碼、開連結或在首頁「已有房間代碼」直接輸入代碼加入。
- 任一方達到 11 分，比賽應在兩端顯示結果；兩人按「再來一場」後沿用**同一間房**重新開賽。
- 一方先按時，另一方會看到「朋友想再打一場」；比賽結束時離線的手機，重新連上後會補收結果；連線超過 3.5 秒沒訊息視為失效並自動重連；朋友離開時可重新掃碼邀請新對手。
- 對戰採用伺服器判定的 WebSocket 即時同步。伺服器約每秒發送 25 次權威狀態（差量快照：只送有變的欄位，每約 3 秒補一份完整狀態；斷線重連、客戶端缺基準時第一份一定是完整的）。手機做本機預測，只在方向或按鍵「有變化」時才送控制指令（沒變化時伺服器沿用，不重複送）。
- 每筆指令帶著上一筆指令在手機上實際跑了幾步（`pn`），伺服器的輸入緩衝照這個步數把每筆指令各自執行完（最多緩衝約 100ms，抖動消失後慢慢吃掉），所以網路抖動只會改變指令到達的時間，不會改變伺服器上的移動結果；快照另外回傳「目前這筆指令已執行幾步」（`k`），手機補播時只補它剩下的部分。
- 手機收到快照後每個畫面幀最多還原一次（網路卡住後湧進來的快照只還原最新一份，事件全保留）。位置校正不是瞬間跳過去，而是保持畫面連續、校正量逐漸消掉；持球時球永遠釘在持球者「平滑後」的手上，身體、雙手 IK 與球使用同一組渲染座標。
- 防守方橫移與跟防加速、起跳干擾與有效火鍋判定提高。
- 投籃按住時間與補扣按下時刻由手機隨指令回報（`hd`、`rs`），伺服器只在 ±0.12 秒內採用，並跟著輸入緩衝一起照步數執行。
- 斷線時暫停本機推進，重新連上後等待伺服器恢復；等待房間時停止多餘的遊戲物理計算。
- iPhone 維持原先的 3D 畫質與自動解析度策略。網路方面採用 RTT 平滑估計、網路回堵限制、依延遲調整本機輸入回放，以及短暫斷網時暫停預測。遊戲畫面顯示網路往返延遲（ms），實際延遲仍受地區、Wi-Fi／行動網路影響。

## 球衣與鏡頭

每支手機固定顯示自己為**黃色球衣／短褲**、對手為**紅色球衣／短褲**，不受房主席位或職業選擇影響，重新開局仍會重新套用。網路位置校正時鏡頭跟隨平滑位置，減少突然晃動。

## 維護注意

遊戲的規則以 `src/sim.js` 為準；目前 `public/index.html` 仍內嵌同一份 `createSim()` 給瀏覽器使用。**修改規則時必須同步 HTML 內的函式內容**（逐字一致，可用 `function createSim` 到 `export` 之間的文字比對），否則單人模式可能與 Workers 伺服器／多人模式不同步。部署前請同時驗證單人與多人模式、出線、計分及攻守轉換。

## 單人進度

- 生涯、技巧圖鑑、每日任務和河濱擂台都只存在手機的 `localStorage`（`dh-save-v1`），不經過伺服器。
- 擂台八關定義在 `public/index.html` 的 `STAGES`。傳說關的打法用 `LV` 旗標（`post`、`wing`、`fade`、`fadeGap`、`drive`）控制，只影響 AI。
- 養成只給稱號、圖鑑和號碼，不改任何對戰數值。
- 新手教學共 8 步，定義在 `public/index.html` 的 `TUT`，每步完成才往下，對手是放水的 `LV.tut`。
