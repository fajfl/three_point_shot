# 斷踝

手機直式 3D 街頭籃球 1 對 1。開房後朋友掃 QR Code 就能連線對打，也可以隨機配對、打電腦、闖擂台或比三分大賽。

## 玩法一覽

| 模式 | 說明 |
| --- | --- |
| 打電腦 | 三種難度，比賽長度可在「設定」選 7／11／21 分 |
| 河濱擂台 | 連闖八關，其中三關是傳說對手 |
| 三分大賽 | 五個點各 5 球共 25 球，每點最後一顆花球 2 分，滿分 30；連進越多綠區越窄，失手後恢復 |
| 新手教學 | 8 步學會所有操作 |
| 開房找朋友 | QR Code、連結或 4 碼房號；房主的比賽長度設定會套用到這間房 |
| 隨機配對 | 排隊等另一位線上玩家，湊到人自動開賽 |

比賽中右上角的 `II` 是暫停／選單（聲音、震動、畫質、操作說明、離開比賽）。單人模式會真的暫停；連線對戰不會暫停，離開算認輸。每場打完會列出雙方的投籃、三分、灌籃、火鍋、抄截、放倒數據。

部署版可以「加到主畫面」當成 App 開（`manifest.json`＋`sw.js`），離線時仍可玩所有單人模式。

## 部署

Cloudflare Workers 匯入這個 repo，部署指令用 `npx wrangler deploy`。設定都在 `wrangler.jsonc`，房間用 SQLite 版 Durable Object，免費方案可用。

## 結構

- `src/worker.js`：把 `/ws/房號` 接到房間、`/mm` 接到配對大廳，其餘路徑給靜態檔案
- `src/room.js`：一間房的裁判，伺服器跑規則，雙方只送操作
- `src/match.js`：隨機配對，把排隊的人兩兩湊成一間房
- `src/sim.js`：籃球規則與物理，手機和伺服器共用
- `public/index.html`：遊戲畫面（內嵌同一份規則）
- `public/sw.js`、`public/manifest.json`、`public/icon-*.png`：加到主畫面與離線用
- `test/`：`node --test` 跑的自動測試
- `tools/sync-sim.mjs`：把 `src/sim.js` 同步進 `index.html`；`tools/lag-proxy.mjs`：本機模擬延遲、抖動與斷線

## 遊戲規則

- 1 對 1，率先累計至少 **11 分**獲勝（可改 7 或 21 分），三分球計 3 分、灌籃計 2 分。
- 新球權在三分線內取得球時，必須先將持球者帶回（踩到）三分線；後撤步可在踩線後直接銜接投籃，提早按住投籃鍵也能接招。
- **籃下**：禁區沒人擋才會灌籃；防守者貼在你與籃框之間（約 1.9 公尺內且比你更靠近籃框）時灌不了，投籃鍵變成**上籃**，搖桿橫推再按是**歐洲步**（側跨一步再回來，途中也會晃人）。上籃被蓋前再按一次投籃鍵是**拉桿**，閃過封蓋但命中率只有約一半。
- 灌籃遭到封蓋時，有約 **0.7 秒**的短慢動作與綠條拉桿救球機會；救球成功後仍只有 **60%** 會進。
- **防守 B 鍵**：點按＝起跳封蓋（放開時才起跳）；按住 0.12 秒以上＝**舉手**，不離地、移動速度減半、不會被假動作騙，干擾約為起跳的六成，也封蓋不了。
- 干擾依防守者正面 120° 扇形的距離而定，背後不干擾；出手離三分線越遠，窗口與命中率**連續**衰減（沒有斷崖），投到對面籃下的「Logo 球」極難；神準期間只吃一半衰減。
- **抄球**：範圍與成功率比舊版略大，落空仍會讓持球者獲得突破加成；鐵閘的抄截與封蓋加成降低。
- **晃人判定窗**：被晃的人要在約 0.26 秒（連線對戰再加 0.06 秒與延遲補償，上限 0.3 秒，最短不低於 0.2 秒）內把搖桿推向同一邊；只看你推的方向，不再因「本來就在往那邊跑」而放過。站定的防守者頂住突破時，持球者會踉蹌 0.3 秒。
- **手感**：A／B 按太早（無法行動時）會緩衝 0.1 秒，一能動就執行；放開搖桿 0.08 秒內按 A 仍用剛才的方向；絕招鍵遠離招式鍵且需**長按 0.25 秒**。連線時投籃按住時間與補扣按下時刻由手機回報，伺服器只在 ±0.12 秒內採用。
- **能量**：進球不再加能量；完美出手 +5、讀懂晃人 +12、抄截 +30、封蓋 +30、斷踝 +30。
- 斷踝失誤只在**當次攻守球權**中累積，球權轉換或重新開球便清零。單人模式需 2 次，朋友對戰需 3 次，並給網路對戰更多反應時間。
- 球若連續 7.5 秒無人撿到，會重開下一個回合。

## 多人連線（房間模式）

- 房主選「開房跟朋友打（QR Code）」，畫面顯示 QR Code 與 4 碼房間代碼，連結和代碼都可以複製。
- 朋友可掃碼、開連結或在首頁「已有房間代碼」直接輸入代碼加入。
- 任一方達到 11 分，比賽應在兩端顯示結果；兩人按「再來一場」後沿用**同一間房**重新開賽。
- 一方先按時，另一方會看到「朋友想再打一場」；比賽結束時離線的手機，重新連上後會補收結果；朋友離開時可重新掃碼邀請新對手。
- 在「設定」填的名字會顯示在對手的記分板上；朋友一打開連結（還沒按加入）房主就會看到他進場。
- **隨機配對**：手機連到 `/mm` 排隊，湊到兩個規則版本相同的人就發一組 `Q` 開頭的房號，雙方自動進房開賽；對手 12 秒沒進場會自動重新排隊，排隊最久 5 分鐘。

### 斷線與重連

- **自己斷線**：立刻重連（第一次 40 毫秒後，之後 0.5、1、2、2.5 秒…），握手卡住 6 秒或 3.5 秒沒收到任何訊息也會重連。超過 0.6 秒才會跳出「連線中斷」狀態卡，一眨眼就接回來的瞬斷不打擾。
- **對手斷線**：比賽暫停，畫面顯示「對手斷線了，還有 N 秒」。2.5 秒內接回來就原地繼續；停更久則從檢查球重新開始這一波。**45 秒**沒回來，判留下的人獲勝。
- **殭屍連線**：連線沒斷但 4 秒沒有任何訊息（手機每秒送一次 ping），伺服器當作斷線處理，並放開那位玩家的所有按鍵，不讓對手跟定格的人打。
- **切到別的 App 或關螢幕**：手機主動斷線讓比賽暫停，回到畫面立即重連。
- **重新整理**：網址帶著房號，連上後伺服器會直接把你送回進行中的比賽。
- **離開比賽**：從選單離開會告訴伺服器，對手立刻獲勝，不必等 45 秒。
- **版本核對**：連線時核對規則版本（`src/sim.js` 的 `VER`）。手機還留著舊版頁面時會自動重新載入一次。
- 等待室閒置 15 分鐘會自動關房；同一支手機重複連線時，舊連線會被關掉。
- 對戰採用伺服器判定的 WebSocket 即時同步。伺服器約每秒發送 25 次權威狀態（差量快照：只送有變的欄位，每約 3 秒補一份完整狀態；斷線重連、客戶端缺基準時第一份一定是完整的）。手機做本機預測，只在方向或按鍵「有變化」時才送控制指令（沒變化時伺服器沿用，不重複送）。
- 每筆指令帶著上一筆指令在手機上實際跑了幾步（`pn`），伺服器的輸入緩衝照這個步數把每筆指令各自執行完（最多緩衝約 100ms，抖動消失後慢慢吃掉），所以網路抖動只會改變指令到達的時間，不會改變伺服器上的移動結果；快照另外回傳「目前這筆指令已執行幾步」（`k`），手機補播時只補它剩下的部分。
- 手機收到快照後每個畫面幀最多還原一次（網路卡住後湧進來的快照只還原最新一份，事件全保留）。位置校正不是瞬間跳過去，而是保持畫面連續、校正量逐漸消掉；持球時球永遠釘在持球者「平滑後」的手上，身體、雙手 IK 與球使用同一組渲染座標。
- 防守方橫移與跟防加速、起跳干擾與有效火鍋判定提高。
- 投籃按住時間與補扣按下時刻由手機隨指令回報（`hd`、`rs`），伺服器只在 ±0.12 秒內採用，並跟著輸入緩衝一起照步數執行。
- 規則用的亂數是可重現的，種子跟著快照走：手機補播時抽到的亂數和伺服器相同，抄截成不成功、火鍋往哪邊彈、投籃進不進，都不會先猜錯再跳回來。
- 「比賽結束」只聽伺服器，結果一定帶著正式比分與數據。
- 斷線時暫停本機推進，重新連上後等待伺服器恢復；等待房間時停止多餘的遊戲物理計算。
- iPhone 維持原先的 3D 畫質與自動解析度策略。網路方面採用 RTT 平滑估計、網路回堵限制、依延遲調整本機輸入回放，以及短暫斷網時暫停預測。遊戲畫面顯示網路往返延遲（ms），實際延遲仍受地區、Wi-Fi／行動網路影響。

## 球衣與鏡頭

每支手機固定顯示自己為**黃色球衣／短褲**、對手為**紅色球衣／短褲**，不受房主席位或職業選擇影響，重新開局仍會重新套用。網路位置校正時鏡頭跟隨平滑位置，減少突然晃動。

## 維護注意

遊戲的規則以 `src/sim.js` 為準；`public/index.html` 內嵌同一份 `createSim()` 給瀏覽器使用。**修改規則後請執行 `npm run sync`**（即 `node tools/sync-sim.mjs`）把它同步進 HTML，並把 `src/sim.js` 開頭的 `VER` 加 1，這樣還開著舊版頁面的手機連線時會自動更新，不會和伺服器各跑各的規則。`npm test` 會檢查兩份是否逐字一致。

## 開發與測試

不需要安裝任何套件（Node 22 以上）。

```bash
npm test                 # 規則自洽與可重現性、亂按測試、房間與配對流程
npm run dev              # 等同 npx wrangler dev：本機跑完整的 Workers＋房間
npm run lag -- --lag 60 --jitter 40 --stall 600 --every 8000
                         # 另開一個視窗：在 :8788 模擬延遲與抖動，再用 http://localhost:8788 開遊戲
npm run lag -- --drop 5000   # 每 5 秒把所有連線切斷一次，測試自動重連
```

部署前請同時驗證單人與多人模式、出線、計分及攻守轉換。

## 單人進度

- 生涯、技巧圖鑑、每日任務、河濱擂台、三分大賽最佳成績、連線勝敗、名字與比賽長度都只存在手機的 `localStorage`（`dh-save-v1`），不經過伺服器。
- 三分大賽的五個投籃點定義在 `public/index.html` 的 `SPOTS`；對手用規則裡的 `G.solo` 停在場邊，綠區倍率是 `G.gwK`。
- 擂台八關定義在 `public/index.html` 的 `STAGES`。傳說關的打法用 `LV` 旗標（`post`、`wing`、`fade`、`fadeGap`、`drive`）控制，只影響 AI。
- 養成只給稱號、圖鑑和號碼，不改任何對戰數值。
- 新手教學共 8 步，定義在 `public/index.html` 的 `TUT`，每步完成才往下，對手是放水的 `LV.tut`。
